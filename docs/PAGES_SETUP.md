# Publish the 100 portfolio via GitHub Pages

The production-ready static site lives in `docs/` on the `main` branch.
No Node, Jekyll theme, external scripts, tokens, backend, or build step is needed
at request time. The `.nojekyll` marker preserves the static files as written.

## One-time Pages activation

With repository admin access:

1. Go to [repository Settings → Pages](https://github.com/Svyable/100/settings/pages).
2. Under **Build and deployment**, choose **Deploy from a branch**.
3. Choose branch **main** and folder **/docs**, then **Save**.
4. After the Pages deployment succeeds, visit **https://svyable.github.io/100/**.

If the site is not yet configured, the address may return 404. Merely committing
`docs/index.html` does **not** activate Pages settings automatically.
The linked account's current GitHub connector cannot modify repository Pages settings.
See [GitHub's official guide](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Update pipeline

The site is **generated**: `scripts/build_site.py` renders every page from the
validated ledgers (`data/*.json`), the probe lab, the Lean catalogue and the
Markdown dossiers. Never edit generated files by hand. After any data change, run:

```sh
python3 scripts/rank.py
python3 scripts/build_site.py
python3 scripts/build_site.py --check
python3 -m unittest discover -s tests -v
```

Commit the regenerated `docs/` tree with the source change. CI fails if any
generated byte is stale, if a file is left over in a generated directory, or if
any internal link or `#fragment` on any page does not resolve.

| Generated path | Source |
|---|---|
| `start/` | reader/reviewer/agent routes with evidence boundaries and direct links to canonical work records |
| `llms.txt` | plain-text advisory discovery for text agents, generated from the same site snapshot |
| `api/agent.json`, `api/agent/tasks.json` | agent contract and a small static runnable work shortlist; claim availability requires a fresh GitHub check |
| `index.html` | ranked list of all 100 in dispatch order (prerendered; JS adds filters, sorts, URL state) |
| `problems/<ID>/` | one page per problem: Lean statement, priority, campaign, probes, milestones, claim triage, provenance, citation |
| `fields/<slug>/`, `atlas/` | field pages; SVG charts with table views |
| `discovery/`, `discovery/<ID>/` | sourced motivated-reasoning trails with dependency links, reusable methods, and explicit evidence boundaries |
| `lab/`, `formal/`, `campaigns/`, `claims/`, `roadmap/`, `ledger/` | lab and structure mines, Lean comparators and the audited Lean registry, cohort jobs + campaigns + attack shapes, 2026 claim triage, roadmap scoreboard, solved ledger |
| `library/<doc>/` | every Markdown dossier, rendered with cross-links and backlinks |
| `api/`, `data/portfolio.json`, `feed.xml`, `sitemap.xml` | JSON/CSV API, legacy snapshot, Atom feed, sitemap |

Hand-written: `assets/` (CSS, JS, favicon), `.nojekyll`, `next/` (the Next 100 explorer)
and the Markdown files in `docs/`. `data/next.json` is generated by `scripts/next.py`.

The standalone [Next 100](https://svyable.github.io/100/next/) explorer uses\n`docs/next/` and the generated `docs/data/next.json` snapshot. Refresh it with\n`python3 scripts/next.py`; CI validates its snapshot and JavaScript.\n\n## Features and boundaries

- Static HTML, no external scripts, fonts, trackers or build step at request time.
- Every problem has a permanent URL; legacy `?focus=M071` links redirect to `/problems/M071/`.
- `/` or Ctrl/⌘-K opens a command palette over problems, campaigns, probes, Lean statements, claims and documents.
- Dark mode follows the system and can be toggled; reduced motion and print styles respected.
- A **portfolio rank** measures editorial priorities, never the probability a claim is true.
- The site refreshes only when the generated tree is rebuilt and committed; it does not fetch live papers or news.
